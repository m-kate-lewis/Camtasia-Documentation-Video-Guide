Writing Scripts

Documentation videos show customers the simplest way to complete a common [COMPANY] process, supporting customer set up and success. This article outlines the style, scope, and pacing you should use when writing scripts for these videos. It also includes an example script to use as a template.

Guidelines

Prioritize clarity, brevity, and maintaining a casual tone. Sentences should flow naturally when read aloud. As with written documentation, state the names of buttons, menus, fields, and other UI elements exactly as they appear.

The scope of a video should be small and specific, and it must relate to a [COMPANY] feature or setting without going into troubleshooting or work-arounds. Identify a single, simple process—or a single, complex step in a larger process—to walkthrough from beginning to end. Add context and caveats when necessary, but do not go into every possible option or special use case. Stick to the “Happy Path.”

Consider pacing as well. Think about how long you would naturally remain on each screen of the walkthrough. For example, if you are clicking through and filling out a long form on screen, write more words for that screen than you would for a screen with a single button click. When read aloud, the script should not exceed three minutes of narration, and two minutes should generally be the goal.
